# 실행 검증 기록

## 환경

2026년 10월 6일, Windows 11의 로컬 CPU에서 확인했습니다. Python 3.12.14, PyTorch 2.14.1+cpu, NumPy 2.5.3, Matplotlib 3.11.2, ipywidgets 8.1.9를 사용했습니다. T4 GPU와 실제 Colab 런타임에서의 실행은 확인하지 않았습니다.

## 코드와 단계 연결

`python -m unittest discover -s tests -v`의 8개 검증이 통과했습니다.

| 검증 | 결과 |
|---|---|
| 미끄러짐의 정확한 전이확률과 실제 샘플 빈도 | 일치 범위 통과 |
| 충돌·구멍·목표의 위치와 보상·종료 판정 | 통과 |
| 생성 지도 30개의 안전한 BFS 경로 | 통과 |
| 고정 예시의 짧은 위험 경로와 최적 정책의 안전한 우회 | 통과 |
| 동일 보상 그룹의 advantage 0 및 학습 제외 | 통과 |
| 학습·검증·테스트 지도 seed 분리와 입력 길이 | 통과 |
| 사전학습→SFT→GRPO, 평가, CPU 체크포인트 재개 | 통과 |
| 노트북 형식·빈 출력·전체 코드 셀 문법 | 통과 |

체크포인트 재개는 사전학습과 GRPO 각각에서 중단 없이 실행한 결과와 파라미터가 정확히 같은지 비교했습니다. GRPO는 모델뿐 아니라 동결 reference·optimizer·난수 상태를 복원합니다.

## 노트북과 화면

최신 저장소를 복제하는 준비 셀을 제외하고, 12개 코드 셀을 `smoke` 프로필로 실제 순서대로 실행했습니다. 단계별 학습 곡선·환경 예측 보고서·미끄러짐 유무 평가·SFT/GRPO 비교·최종 테스트까지 실행했습니다. 선택적 Drive·다운로드·생략 실험은 기본 비활성 상태로 실행했습니다.

ipywidgets의 등록된 버튼 콜백을 호출해 예측·실제 한 걸음·정책 한 걸음·자동 실행·초기화를 확인했습니다. 생성한 예측 확률 그림과 SFT/GRPO 비교 그림을 렌더링해 확인했습니다. 이 검증은 로컬 Python과 Matplotlib 렌더링 기준이며 Colab 브라우저의 위젯 통신을 검증한 결과는 아닙니다.

`smoke`는 4회 사전학습·4회 SFT·2회 GRPO만 수행합니다. 이 상태의 테스트에서 모델은 목표에 도달하지 못했습니다. 정상적인 코드 연결 확인 결과이며 학습된 능력이나 성능 개선의 근거로 사용하지 않습니다.

## 줄인 CPU 학습 예산의 결과

기본 T4 모델과 같은 809,157개 파라미터를 사용하되 학습 지도 128개, 사전학습 300회, SFT 600회, GRPO 20회로 줄여 실행했습니다. GRPO는 업데이트당 지도 4개·그룹당 후보 4개를 사용했습니다. 지도 크기·시간 제한·보상·학습률은 기본 설정과 같습니다. 검증·테스트는 각각 지도 8개, 지도당 4회입니다. seed는 42입니다.

사전학습의 검증 다음 위치 샘플 정확도는 23.4%, TV distance는 0.845, KL은 2.254였습니다. 아직 충분히 학습된 확률 예측기로 볼 수 없습니다. 학습 로그의 cross-entropy는 첫 업데이트 3.909, 마지막 업데이트 2.654였습니다. 서로 다른 샘플 배치의 수치이며 정식 성능 비교는 검증 지표를 사용해야 합니다.

| 최종 테스트 정책 | 도착률 | 추락률 | 시간초과율 | 평균 보상 |
|---|---|---|---|---|
| SFT | 62.5% | 25.0% | 12.5% | 0.022 |
| SFT→GRPO | 37.5% | 37.5% | 25.0% | −0.528 |
| BFS 재계획 | 90.6% | 9.4% | 0.0% | 0.702 |
| 확률적 환경의 최적 정책 | 100.0% | 0.0% | 0.0% | 0.870 |

이 실행에서는 **GRPO가 SFT를 개선하지 못했습니다.** 기본 T4 예산 전체의 결과가 아니며 지도 8개·초기화 seed 하나의 관측입니다. 32회 시행은 지도 8개를 반복한 것이므로 독립된 지도 32개의 실험으로 해석하지 않습니다. 검증 지도와 테스트 지도에서도 결과 차이가 컸습니다. 이 수치로 단계의 필요성이나 일반적인 성능을 입증하지 않습니다.

## 확인하지 않은 범위

- T4의 실제 최고 메모리 사용량과 단계별 실행 시간.
- 기본 `t4` 예산 전체를 학습했을 때의 수렴과 GRPO 성능 개선.
- 여러 초기화 seed에서 각 단계의 통계적으로 안정적인 이득.
- Colab 서비스의 화면 캐시 자체를 제어하는 기능. 배지의 커밋별 URL과 최신 코드 복제로 실행 버전을 구분합니다.

학습 로그, 평가 JSON, 단계별 체크포인트는 각 실행의 출력 폴더에 생성됩니다. 서로 다른 설정의 결과를 합쳐서 성능을 주장하지 않습니다.
